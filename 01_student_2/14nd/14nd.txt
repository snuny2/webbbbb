공격자가 임의의 파일을 서버에 업로드 하는 공격
> 서버에서 파일업로드는 엄청 위험한 기능

파일: 데이터 set

원칙
> 이용자가 업로드할 수 있는 파일을 검증을 해서 업로드 시켜줘야함


이용자가 파일을 서버에 올리고 보려면
서버는 그냥 보여주지않고 파일을 실행 시켜서 줌
> 즉 공격작가 악성파일을 올리고 다른 이용자가 확인시 
이용자의 컴퓨터를 장악할 수 있음


Reverse Shell

Shell
> 명령을 받고 컴퓨터가 실행을 함
공격자가 쉘을 이용시 피해자의 포트를 여는데 이건 확인이 쉬워서
반대로 피해자가 공격자의 쉘로 오도록 함
> 그래서 리버스쉘을 이용해서 피해자의 컴퓨터를 장악할 수 있음


Web Shell
> 파일을 업로드하고 웹서버가 해당 파일을 실행 시킨 후 보여주는 것


만약 아무 파일이나 올릴 수 있다면?
웹 서버의 루트 경로의 index 파일을 덮어쓸 수 있으면?
> 디페이스 공격: index파일을 변경 시킬 수 있음

HTML파일을 올릴 수 있다면?
>피싱 페이지를 구글, 네이버 등으로 하거나
> stored xss파일도 올릴 수 있음


Web Shell
> 인터넷을 통한 쉘
> 웹 서버에서 실행되는 웹 서버 측 스크립트

만약 php만 실행되는 컴퓨터라면
이 컴퓨터엔 php가 아닌 다른 파일이 올라가면 실행조차 이루어 지지않음
> 언어마다 다름


정해진 프로세스가 없고 하나하나 찾아가며 알아가야함

1. 정상 파일 올려보기
> 어디에 업로드 되는지 확인
>> 업로드 한 파일을 다시 가져오는 곳
>> 버프 스윗으로 응답 코드를 살펴보기
>> 그 후 다른 파일을 업로드 후 응답을 보고 확인 해보기

> 게시글에 파일을 업로드 하고 다운하면 버프 스윗에 응답에 나올 수도 있음



업로드 된 경로가 유추되는 곳

- fileupload.php > HTTP RESPONSE

- HTML 소스코드
- 파일 다운로드: 다운을 해서 알아봄
- SQL Injection



Bypass

> 블랙 리스트 기반 vs 화이트 리스트 기반
>> 보안적으론 화이트 리스트

만약 php를 막는다면
업로드 되는 파일 이름 확인
파일 이름 맨 끝에 확장자 추출해서 파일 업로드 중단

우회법
> 대소문자 혼용 
>> pHp, PhP등

> 다른 확장자명 사용
다른 확장자로도 실행이 이루어 짐


코드를 잘못 짜면
hello.jpg.php 를 php파일이 아닌 jpg파일로 인식 할 수 있음

하지만

hello.php.jpg 이렇게 하면 이미지 파일로 구분함
> 업로드가 되도 그냥 이미지 파일을 업로드 한 것
>> 이걸 실행하려면 다른 취약점을 이용 해야함


파일이름에 Null Byte 삽입
> Null Byte = %00
> hello.php%00.jpg
>> 서버는 널 바이트가 있으면 거기서 끝냄
>> 즉 업로드엔 이미지 파일, 확인 시엔 php파일로 됨
>>> 요즘엔 이렇게 우회될 가능성이 낮음. 거의 최신거
진짜 만약에 가끔 볼 수 있을 수 있다



만약 이미지 파일만 올릴 수 있는 페이지라면
> 버프 스윗으로 컨텐츠 파일 검증을 수정하여 업로드를 할 수 있음
>> 확장자와 컨텐츠 파일 구분을 같이 신경써야함


파일 시그니쳐
파일의 헥사 값을 보면 맨 앞에 파일 구분이 써있음

php파일은 이미지 파일 헥사값 사이에 넣을 수 있음
> 버프스윗으로 파일 업로드 형식을 수정하고 확인 시 삽입된 코드를 확인할 수 있음



일구화목마 = 한 줄 웹쉘



업로드 되는 경로에 따라 권한을 정함
> php파일을 업로드 하면 저장된 경로의 파일들은 실행이 안됨
>> 업로드시 경로를 바꾸어 파일을 업로드 해 볼 수 있음
>> 버프에서 Content-Disposition 에서 파일앞에 ../로 상위 폴더에 저장을 해 우회 할 수 있음


디렉토리 별로 실행할 수 있는 파일 확장자 지정
> .asd 를 .php로 지정하여 qweasd.asd를 php파일로 인식하여 실행을 할 수도 있음
